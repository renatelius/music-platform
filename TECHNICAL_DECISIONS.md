# Technical Decisions (ADR log)

Журнал архитектурных решений. Каждое решение: контекст → решение → последствия. Статусы: `Принято`, `Предложено`, `Заменено`.
Версии проверены 2026-11-04; перед установкой каждая фиксируется в lock-файле.

## ADR-001 — Целевые платформы: Web, Windows, Android, iOS
**Статус:** Принято · 2026-11-04 · Решение заказчика

**Решение.** Четыре клиента на одной backend-платформе: единый аккаунт, библиотека, подписка, история, рекомендации, очередь и прогресс синхронизируются между устройствами.

**Последствия.**
- Общая бизнес-логика и типы — в общих TS-пакетах монорепозитория; клиенты остаются тонкими.
- Нужна серверная модель «сессии воспроизведения» (какое устройство играет, позиция, очередь) с real-time-каналом (WebSocket).
- Сборка iOS требует macOS/Xcode или облачной сборки (Expo EAS); на текущей Windows-машине локально собрать iOS нельзя.
- Windows-клиент на Tauri 2 требует Rust toolchain и WebView2 (установлены 2026-11-04).

## ADR-002 — Гибридный музыкальный каталог
**Статус:** Принято · 2026-11-04 · Решение заказчика

**Решение.** Четыре источника контента в одной модели данных:
1. Лицензированные каталоги (через провайдеров/дистрибьюторов по договору).
2. Независимые исполнители (Artist Studio, загрузка с подтверждением прав и модерацией).
3. Загрузки пользователей в личную облачную коллекцию (приватные, без публичной раздачи).
4. Локальные файлы на устройстве пользователя.

**Последствия.**
- У каждого трека обязательные `source` и `rights` (территории, режимы стрим/офлайн/превью, срок действия). Плеер и поиск обязаны их учитывать.
- Источники маркируются в UI; личная и локальная музыка не смешивается с каталогом без явной метки.
- Наличие публичного API у сервиса ≠ право ретранслировать аудио.
- Нужен конвейер модерации и проверки прав (audio fingerprinting) для загрузок.

## ADR-005 — Монорепозиторий pnpm + Turborepo
**Статус:** Принято

**Решение.** Один репозиторий; структура — ARCHITECTURE.md §3. Пакеты общаются только через публичный `index.ts`; запрет циклических зависимостей (линтер).

## ADR-006 — Модульный монолит вместо микросервисов
**Статус:** Принято · 2026-11-04

**Решение.** `apps/api` (HTTP + WS) и `apps/worker` (очереди) — два процесса из одного кода; модули по доменам с явными интерфейсами. Python-ML — отдельный сервис только с Phase 5.
**Почему.** Требование BRIEF_v2 §10; меньше инфраструктуры, проще транзакции и отладка. Выделение сервиса = перенос модуля + замена вызова на HTTP/очередь.

## ADR-007 — Собственная аутентификация по стандартам
**Статус:** Принято · 2026-11-04

**Решение.** Свой модуль auth в NestJS: argon2id, JWT access 15 мин, ротируемые refresh-токены (хранится хэш), отзыв сессий по устройствам. Вход через Google/Apple (OIDC) — Phase 3.
**Альтернативы.** Keycloak/Ory/Zitadel — полноценный IdP, но ещё один тяжёлый сервис и сложная настройка на старте. Архитектура допускает переход на внешний IdP позже: клиенты используют стандартные токены.

## ADR-008 — Поиск: Postgres сначала, OpenSearch при необходимости
**Статус:** Принято · 2026-11-04

**Решение.** Модуль `search` работает через интерфейс `SearchPort`. Итерации MVP — реализация на PostgreSQL (FTS + pg_trgm для опечаток). OpenSearch подключается в Phase 2 (тексты песен, многоязычные анализаторы, фасеты по настроению/темпу) с синхронизацией через очередь.
**Почему.** На тестовом каталоге (тысячи треков) Postgres даёт тот же результат без ещё одного сервиса на 1–2 ГБ ОЗУ; OpenSearch вводим, когда появится функция, которую Postgres не тянет. Без «технологий ради моды» (BRIEF §7).

## ADR-009 — Доставка аудио: файлы рендиций + Range, HLS позже
**Статус:** Принято · 2026-11-04

**Решение.** Транскодированные файлы (AAC 96/160/256, Opus 160, FLAC при lossless-исходнике) отдаются по подписанным ссылкам с Range-запросами через CDN. Адаптивный битрейт — выбор рендиции на уровне трека по измеренной скорости. HLS/DASH fMP4 — для длинного контента в Phase 5–6.
**Почему.** Для 3–5-минутных треков сегментация даёт мало, а gapless/crossfade и офлайн-кэш с целыми файлами реализуются надёжнее на всех 4 платформах.

## ADR-011 — Синхронизация: журнал изменений + WebSocket
**Статус:** Принято · 2026-11-04

**Решение.** Монотонный `user_change_seq`, идемпотентные мутации, рассылка через WS (Redis pub/sub), догоняющий запрос `/sync/changes?since=`. Сессия воспроизведения — одна активная на пользователя, Handoff через захват сессии. Подробно — ARCHITECTURE.md §7.
**Альтернативы.** CRDT (Yjs/Automerge) — избыточно для лайков и плейлистов; рассмотреть для совместных плейлистов в Phase 6.

## ADR-012 — Тестовый каталог MVP: Creative Commons из FMA
**Статус:** Принято · 2026-11-04

**Решение.** CLI `tools/catalog-import` загружает выборку (≈ 300–1000 треков) из открытого датасета Free Music Archive, оставляя **только CC0 / CC BY / CC BY-SA**; лицензия и атрибуция хранятся в `track_rights` и показываются в UI. Каталог помечен в интерфейсе как «Открытый каталог (Creative Commons)».

## ADR-014 — Каркас API (итерация I2a)
**Статус:** Принято · 2026-11-04

**Решение.**
- **NestJS 12.3, ESM** (`"type": "module"`, NodeNext). Express-адаптер. Сборка — `tsc` (не Nest CLI): меньше зависимостей, тот же результат.
- **Конфигурация** — zod-схема переменных окружения (`src/config/env.ts`); приложение не стартует с неверным `.env`, в ошибке — имя переменной без значения.
- **Ошибки** — единый `ProblemExceptionFilter` → RFC 9457 из `@mp/contracts`; детали 5xx не раскрываются; query-строки не попадают в ответы и логи.
- **Логи** — встроенный `ConsoleLogger` NestJS (JSON-режим в проде, структурные параметры с v12) вместо pino: на этом этапе этого достаточно, без лишней зависимости.
- **Rate limit** — свой фиксированный счётчик окна в Redis (общий для всех инстансов). Глобальный лимит по IP fail-open; для auth в I2b — fail-closed.
- **Redis-клиент — ioredis 5.x**, а не только что вышедший 6.0: у 6.0 пока нет опубликованного описания изменений. Пересмотреть позже.
- **Интеграционные тесты запускают скомпилированный `dist/`**: Vitest-трансформер не генерирует decorator metadata, на которых основан DI NestJS, а `tsc` генерирует. Поэтому `test` в `apps/api` зависит от `build` (turbo), тесты идут на реальных Postgres/Redis/S3 из Docker и только на БД с именем `*_test` (защита от случайного запуска на рабочей БД).
- **Миграции** — схема Drizzle (`src/db/schema.ts`) — источник правды; SQL генерирует `drizzle-kit generate`, файлы коммитятся; CI проверяет, что миграции совпадают со схемой. Первичные ключи — UUID v7 (`uuidv7()` в PostgreSQL 18).
- **Расширения PostgreSQL** (`citext`, `pg_trgm`, `vector`, `unaccent`) создаются при подготовке БД (init-скрипт Docker, в проде — при провижининге), а не миграциями.

## ADR-015 — Аутентификация (итерация I2b)
**Статус:** Принято · 2026-11-04 · уточняет ADR-007

**Решение.**
- **Пароли — встроенный Argon2id Node.js** (`crypto.argon2`, Node ≥ 24.7) вместо npm-пакета `argon2`: без нативной сборки на Windows/CI. Параметры OWASP: m = 19 МиБ, t = 2, p = 1; формат PHC; NFKC-нормализация; `needsRehash` — автоматическое усиление хэша при входе. Для неизвестных email выполняется такая же работа (выравнивание времени ответа).
- **Access-токен** — JWT HS256 (библиотека `jose`) на 15 минут, `sub` = пользователь, `sid` = сессия. На каждом запросе проверяется, что сессия жива — выход и отзыв сессии действуют сразу, а не через 15 минут. Цена — один индексированный запрос к БД; при росте нагрузки — кэш в Redis.
- **Refresh-токен** — случайные 256 бит, в БД только SHA-256. Ротация при каждом обновлении в рамках «семейства»; повторное предъявление уже использованного токена = кража → отзывается всё семейство и пишется событие аудита.
- **Доставка refresh-токена:** браузер — cookie `mp_refresh` (`HttpOnly; SameSite=Strict; Path=/auth`, `Secure` в проде); нативные клиенты (`X-Client-Type: native`) — в теле ответа, хранение в Keychain/Keystore/Credential Manager. Следствие: веб-клиент должен обращаться к API с того же сайта — в разработке через прокси Next.js (I3).
- **Email-ссылки** (подтверждение 24 ч, сброс пароля 1 ч) — одноразовые, хранятся хэшем, новая ссылка гасит старые. Сброс пароля подтверждает email и завершает все сессии.
- **Регистрация** возвращает 409 при занятом email (понятнее пользователю; перебор ограничен лимитом 20/час на IP). «Забыли пароль» отвечает одинаково для любых email (без раскрытия аккаунтов).
- **Лимиты** (Redis, fail-closed — при недоступности Redis вход временно запрещён, 503): вход 10/15 мин на email и 50/15 мин на IP, регистрация 20/ч на IP, сброс пароля 3/ч на email, повторное письмо 3/ч.
- **Почта** — nodemailer по SMTP (локально Mailpit); письма ru/en по языку пользователя. Ошибка отправки не ломает регистрацию — письмо можно запросить повторно.
- **Аудит** — `audit_events`: регистрация, вход, неудачный вход, обнаружение кражи токена, выходы, отзыв сессии, подтверждение email, запрос и сброс пароля.
- **OpenAPI `/docs` перенесён** в I5: генерация из zod-контрактов будет настроена, когда API каталога даст достаточный объём эндпоинтов. Сейчас контракт — `packages/contracts`.

## ADR-016 — Название, дизайн-система и веб-клиент (итерация I3)
**Статус:** Принято · 2026-11-04

**Решение.**
- **Название продукта — ReMusic** (решение заказчика). Внутренний npm-scope пакетов остаётся `@mp/*`, репозиторий — `music-platform`: это не видно пользователям, переименование не даёт ценности.
- **Визуальное направление** (выбрано студией, заказчик доверил выбор): тёмная «кинематографичная» эстетика как основа — глубокий почти чёрный фон, фирменный градиент фиолетовый → коралловый (`#7C5CFF → #FF6B57`), крупная плотная типографика (Inter с кириллицей). Полноценная светлая тема. Тема по умолчанию — как в системе; выбор сохраняется.
- **`@mp/design-tokens`** — источник правды: семантические цвета (фон, поверхность, текст, акцент, состояния), тени, радиусы, анимации. Генерирует `tokens.css` (CSS-переменные `--mp-*`, светлая/тёмная/по системе — работает до загрузки JS). Тот же TS-объект пойдёт в React Native (Phase 3). **Каждая пара «текст/фон» проверяется тестом на контраст WCAG AA (≥ 4.5:1)** в обеих темах.
- **`@mp/ui`** — React-компоненты на Tailwind CSS v4 (Button, TextField, PasswordField, Alert, Card, Badge, SegmentedControl на нативных radio, Avatar, Logo, иконки). Доступность: связка label/ошибок через aria, `role=alert` для ошибок, видимый фокус, `prefers-reduced-motion`.
- **`@mp/i18n`** — свои словари (en — источник, ru), типобезопасные ключи (отсутствующий перевод = ошибка компиляции), интерполяция, определение языка: cookie → Accept-Language → en; заготовка RTL. Без тяжёлых i18n-библиотек: объём строк пока небольшой.
- **`@mp/api-client`** — общий клиент для всех платформ: access-токен только в памяти, обновление «одно на клиент» (single-flight) + **Web Locks между вкладками**, повтор запроса после 401, нативный режим (refresh-токен в защищённом хранилище ОС).
- **Веб-клиент — Next.js 16.4 (App Router)**, проксирует API под `/api/*` (same-origin): refresh-cookie остаётся `HttpOnly; SameSite=Strict`, CORS не нужен. Cookie получает `Path=/api/auth` (`AUTH_COOKIE_PATH`). API доверяет `X-Forwarded-For` только от прокси на той же машине (`TRUST_PROXY=loopback`) — лимиты по IP работают для реальных клиентов.
- **Гонка обновления токена в двух вкладках:** токен, ротированный < 10 с назад, даёт 409 «повторите с новым» вместо отзыва всех сессий; клиент повторяет один раз. Повтор старого токена позже по-прежнему считается кражей.
- **Защита страниц — на клиенте** (токен в памяти, серверу страниц он неизвестен): экран загрузки → вход с возвратом на исходную страницу (`next`, только относительные пути — без open redirect).
- `PATCH /me` — смена имени и языка (язык писем = язык профиля).

## ADR-017 — Конвейер аудио и тестовый каталог (итерация I4)
**Статус:** Принято · 2026-11-04 · уточняет ADR-009 и ADR-012; источник и объём — решение заказчика

**Контекст.** Готовые наборы FMA (`fma_small/medium/large`) содержат только 30-секундные отрывки — для полноценного плеера (рубеж 1, критерий 5) не подходят. Целые треки есть только в полном архиве (917 ГиБ), а на дисках свободно ~70 ГБ (B:) и ~19,5 ГБ (C:).

**Решение.**
- **Источник — Hugging Face `benjamin-paine/free-music-archive-full`** (пересборка полного FMA в Parquet, 972 части по 60 МБ–2 ГБ, медиана ~0,5 ГБ, ~110 треков в части). Проверено на части `train-00040`: аудио — целые треки MP3 128 kbps / 44,1 кГц; у каждого трека есть `title`, `artist`, `album_title`, `url`, `artist_url`, `license` и флаги `allow_commercial_use`, `allow_derivatives`, `require_attribution`, `require_share_alike`.
- **Отдельной «коммерческой» конфигурации в репозитории нет** (есть только `default`) — фильтруем сами.
- **Фильтр лицензий — белый список имён**, а не номеров: CC0 1.0, Public Domain Mark 1.0, CC-BY 1.0–4.0, CC-BY-SA 1.0–4.0; дополнительно `allow_commercial_use = Yes` и `allow_derivatives = Yes`. Всё прочее (NC, ND, Sampling+, FMA Common Law, Free Art License, FMP) отклоняется. Номер лицензии переводится в имя по `class_label` из YAML-разметки набора — таблица в тексте его README пронумерована иначе (нет Public Domain Mark).
- **Лицензии распределены кусками** (треки идут по альбомам: в `train-00040` все 110 — CC-BY-NC-SA 3.0). Поэтому CLI сначала читает только метаданные частей (без колонки `audio`) и выбирает части с подходящими треками, затем скачивает только нужное. Подходящих лицензий ~8–9 % длительности набора — на 300 треков хватает с запасом.
- **Объём тестового каталога — 300 треков** (≈ 3–5 ГБ исходников и рендиций).
- **Честное качество.** Все исходники FMA — MP3, значит все рендиции `lossy` (`classifyQuality`); FLAC и Hi-Res на этом каталоге не появятся. Правило: **рендиция не выше битрейта исходника** (из MP3 128 kbps — только AAC 96 и Opus/AAC ≤ 128, без «раздутых» 256). Ветки lossless/Hi-Res проверяются синтетическими файлами, которые генерирует FFmpeg в тестах.
- **Атрибуция** (автор, название, ссылка на трек на FMA, лицензия со ссылкой на текст) хранится в `track_rights` и обязательна к показу (I5).

**Последствия.**
- Итерация I4 делится на **I4a** (worker и конвейер на синтетических файлах) и **I4b** (импорт каталога).
- Импорт зависит от доступности Hugging Face; скачанные части кэшируются локально (`B:`, вне репозитория), повторный импорт не дублирует записи.

**Уточнение (2026-11-05) — где живёт worker.** Worker — **второй процесс того же `apps/api`** (`src/worker/main.ts`), а не отдельный `apps/worker`. ADR-006 и так описывает их как «два процесса из одного кода»; так worker без переноса и дублирования использует схему БД, миграции, проверку `.env`, подключения к Postgres/Redis/S3 и тестовую инфраструктуру API. Вынести его на отдельную машину это не мешает: та же сборка, другая команда запуска. Отдельный пакет `packages/db` заведём, когда базу понадобится ещё кому-то (например, `tools/catalog-import`, если ему будет мало постановки задач в очередь).

**Слой FFmpeg** (`apps/api/src/media`) — обычные функции без NestJS: `probeAudio` (ffprobe → формат в терминах `AudioFormat` из `@mp/contracts`), `analyzeAudio` (один проход декодирования: EBU R128 `ebur128=peak=true`, true peak, ReplayGain 2.0 = −18 LUFS − I, ошибки декодера через `-loglevel level+info`), `checkMediaTools` (наличие ffmpeg/ffprobe и энкодеров aac, libopus, flac). Бинарники вызываются без shell, пути — `FFMPEG_PATH` / `FFPROBE_PATH` или PATH. Ошибки — `MediaError` со стабильным кодом (`unreadable`, `no_audio_stream`, `unsupported_codec`, `tool_missing`, `timeout`), он же станет `failure_reason` трека. Тесты — только на синтетике, которую генерирует сам FFmpeg (эталонный тон 997 Гц −23 dBFS = −23 LUFS, тишина, FLAC 16/44.1 и 24/96, MP3 128); в CI FFmpeg ставится из apt, тесты не зависят от его версии.

**Конвейер и очередь** (`apps/api/src/worker`).
- **Очередь — BullMQ 6.5** (Redis), очередь `ingest`, одна задача на трек, `jobId` = id трека (повторная постановка ожидающего трека ничего не делает), 3 попытки с экспоненциальной паузой. Источник правды о статусе — БД (`tracks.status`, `failure_reason`), поэтому завершённые задачи из Redis удаляются. Префикс ключей `QUEUE_PREFIX` (тесты берут уникальный).
- **Процесс worker — обычный Node-процесс без NestJS DI** (`src/worker/main.ts`): зависимости (БД, S3, пути FFmpeg) передаются явно — проще тестировать, нет decorator metadata. Запуск: `pnpm --filter @mp/api worker`; `dev.bat` поднимает его рядом с API и перезапускает после успешной сборки.
- **Шаги:** мастер из `mp-masters` → ffprobe → проверки (длительность ≥ `INGEST_MIN_DURATION_SEC`, по умолчанию 30 с; не тишина; ≤ 10 ошибок декодера) → громкость → рендиции → `mp-media` (`tracks/{id}/{aac-160|opus-128|flac-24-96000}.{ext}`) → одна транзакция в БД: рендиции заменяются целиком, громкость upsert, трек `ready` с форматом исходника. Файлы загружаются до записи в БД — каждая строка `track_assets` указывает на существующий объект.
- **Лестница рендиций:** AAC 96/160/256 (m4a, частота исходника, > 48 кГц → 44,1/48 кГц той же «семьи»), Opus 160 (webm, 48 кГц); у lossy-исходника битрейт ограничен исходным и округлён вниз до стандартного (MP3 128 → AAC 96, AAC 128, Opus 128; VBR 191 → 96/160/160). FLAC 16-bit — только для lossless-мастера; FLAC в исходном разрешении (до 24 bit) — только для Hi-Res. Поэтому уникальность рендиции — по кодеку, битрейту, частоте и битности.
- **Отказы** (не повторяются): `no_master`, `master_missing`, `too_short`, `silence`, `corrupt`, `source_bitrate_too_low`, `unreadable`, `no_audio_stream`, `unsupported_codec`. Временные сбои (S3, БД, FFmpeg упал) — исключение и повтор; после последней попытки — `internal_error`.

**Уточнение (2026-11-05) — импорт тестового каталога (I4b).**
- **Где что лежит.** `tools/catalog-import` — адаптер источника: чтение Hugging Face, белый список лицензий, отбор, CLI, отчёт. Все записи в БД — в `apps/api/src/catalog/ingest.ts` (`ensureSource`, `upsertCatalogTrack`, `attachMaster`, `checkCatalog`, `deleteSourceCatalog`), конвейер — прежний `processTrack`. Инструмент подключает `@mp/api` через `exports` пакета (собранный `dist`), поэтому схема, конфиг и подключения не дублируются, а отдельный `packages/db` по-прежнему не нужен.
- **Лицензии — общее правило в `@mp/contracts`** (`OpenLicense`, `OPEN_LICENSE_URL`, `formatAttribution`): им же воспользуются клиенты в I5. Имена FMA сопоставляются с каноническими («CC-BY 4.0» → «CC BY 4.0»); кроме имени, флаги строки `allow_commercial_use` и `allow_derivatives` должны быть `Yes` — при любом расхождении трек пропускается (`license_flags_not_open`).
- **Чтение Parquet — `hyparquet`** (чистый JS, без нативных модулей) через HTTP Range: сначала только колонки метаданных (одна выборка на row group, кэш JSON в `CATALOG_CACHE_DIR`, по умолчанию `~/.cache/remusic/catalog-import`, отдельно для каждого коммита набора), затем колонка `audio` только у row group, где есть отобранные треки. Аудио части (у частей один row group, ~0,5 ГБ) приходится скачивать целиком, сколько бы треков из неё ни понадобилось: первый запуск показал 508 МБ ради одного трека. Поэтому сначала читаются метаданные всех 972 частей (~0,5 МБ на часть, один раз, затем кэш), части сортируются по числу подходящих треков, и аудио скачивается только у самых «плотных» — лицензии идут альбомами, так что 300 треков набираются из немногих частей. Сколько будет скачано, заранее показывает `--dry-run`. Ревизия набора фиксируется до коммита (`main` → sha) и пишется в отчёт.
- **Идентификаторы.** `external_id` трека — путь его страницы на FMA (`/music/Artist/Album/Track`), исполнителя и альбома — пути их страниц; трек без альбома становится синглом (`single:<путь трека>`). По этим ключам повторный запуск находит записи: готовые пропускаются, отклонённые конвейером не повторяются без `--retry-failed`, прерванные дообрабатываются.
- **Права:** `allow_stream` и `allow_offline` = true (все разрешённые лицензии допускают копирование), территории — весь мир, атрибуция — «"Название" by Исполнитель, licensed under CC BY 4.0» (для CC0 и PDM — своя формулировка), ссылки на текст лицензии и страницу трека обязательны.
- **Разнообразие:** части набора просматриваются в детерминированном перемешанном порядке (`--seed`), не больше 10 треков с одного альбома (`--max-per-release`).
- **Проверка результата** (`checkCatalog` + HEAD в S3): ноль лицензий вне белого списка среди всех треков источника, у каждого готового трека есть права, ссылка на лицензию, атрибуция, ссылка на источник и рендиции, каждый объект рендиции есть в S3 нужного размера. Код выхода 0 — только если готово ≥ `--target` и все проверки пройдены. `setup.bat` запускает импорт: первый раз он скачивает несколько ГБ, потом только проверяет каталог.
- Обложек и жанров в наборе нет (жанры — номера, таблицы жанров в схеме пока нет): обложки — заглушка в I5, жанры — при проектировании поиска I5.

## ADR-018 — API каталога и поиск (итерация I5a)
**Статус:** Принято · 2026-11-05 · уточняет ADR-008; доступ только после входа — решение заказчика

**Решение.**
- **Эндпоинты** (`apps/api/src/catalog`, все за `AuthGuard`): `GET /catalog/home`, `/catalog/releases/:id`, `/catalog/artists/:id`, `/catalog/tracks/:id`, `/catalog/search?q=&limit=`, `/catalog/search/suggest?q=&limit=`. Контракты — `@mp/contracts` (`catalog.ts`): `TrackDto`, `ReleaseSummary/Detail`, `ArtistSummary/Detail`, `CatalogHome`, `SearchResults`, `SuggestResults`.
- **Правило видимости — одно на все запросы:** трек показывается, только если он `ready`, у него есть рендиции и действующее право `allow_stream` без территориальных ограничений (определения страны пользователя пока нет — трек с территориями не показывается нигде, а не показывается «всем»). Релиз и исполнитель видны, только если у них есть видимый трек; счётчики и длительности считают только видимые треки. Невидимое отвечает 404, а не пустой страницей.
- **На каждом треке** — лицензия, ссылка на её текст, атрибуция и ссылка на источник (ADR-017), и честное качество: лучшая рендиция (`tier` + `format`, клиент показывает `describeFormat`). Ссылки в ответах — только http(s) (`HttpUrl`): их рендерят как `<a>`.
- **Главная — только разделы на реальных данных:** размер каталога, «Недавно добавленные» (по дате импорта), «Треки дня» (случайная выборка, меняется раз в сутки, одинакова для всех — не выдаётся за рекомендации), исполнители с наибольшим числом треков. «Популярного» и «Для вас» нет, пока нет данных о прослушиваниях (I7, Phase 5).
- **Запросы** — функции над БД (`queries.ts`), JSON собирается в PostgreSQL и проверяется схемой контракта при каждом ответе: расхождение API и контракта — ошибка 500 с логом, а не тихо неверные данные.
- **Поиск (уточнение ADR-008):** по названиям и именам — триграммы pg_trgm, а не стемминг FTS: строки короткие и на разных языках, стемминг под один язык портит имена, а триграммы дают опечатки. Нормализация `mp_search_norm` = `lower(unaccent())` (регистр, акценты, ё → е), GIN-индексы по ней на `artists.name`, `releases.title`, `tracks.title` (миграция `0003_catalog_search`, своя SQL-миграция: drizzle-kit не управляет функциями и индексами по выражениям). Совпадение: подстрока или нечёткое совпадение слова (`<%`, порог 0,4 на время запроса — при стандартных 0,6 одна неверная буква в середине слова уже не находится). Ранжирование: точное > начало > начало слова > подстрока, плюс сходство; трек и релиз находятся и по исполнителю (с весом 0,8). Запросы короче 3 символов — только по началу слов. Ввод пользователя никогда не становится шаблоном LIKE (`%`, `_`, `\` экранируются). FTS (`tsvector`) появится вместе с длинными текстами (описания, тексты песен).
- **OpenAPI 3.1** — `GET /openapi.json` и `GET /docs` (HTML без скриптов, свой строгий CSP), собираются из тех же zod-схем (`z.toJSONSchema`) — новых зависимостей нет. Список операций — `src/docs/openapi.ts`; тест проверяет, что каждая описанная операция существует. По умолчанию включено вне production (`API_DOCS`).
- `setup.bat` проверяет каталог на dev-базе теми же функциями (`catalog:smoke`): главная, релиз, исполнитель, поиск с опечаткой, подсказки.

**Последствия.** Экраны I5b используют только эти эндпоинты. Территории, жанры, обложки и FTS — отдельными решениями, когда появятся данные.

**Уточнение (2026-11-05) — экраны каталога (I5b).**
- **Маршруты веба:** `/` (главная), `/search?q=` (поиск, запрос в адресе — ссылкой можно поделиться, «назад» работает), `/release/:id`, `/artist/:id`. Отдельной страницы трека нет: подсказка и ссылка на трек ведут на его релиз (в подсказку добавлен `releaseId`).
- **Данные — только из API каталога** через `@mp/api-client` (`catalogHome`, `release`, `artist`, `track`, `search`, `suggest`) и общий хук `useApi`: состояние загрузки, «не найдено» (404 и 422 на неверный id в адресе) и ошибка с кнопкой «Повторить»; ответ на устаревший запрос отбрасывается.
- **Поиск** — combobox по WAI-ARIA: подсказки через 200 мс после ввода, стрелки, Enter, Escape; устаревшие подсказки не заменяют свежие; при ошибке подсказок поиск продолжает работать.
- **Честная маркировка:** на главной сказано, что это тестовый каталог Creative Commons из FMA; качество — лучшая рендиция (`describeFormat`, у lossy — «AAC 128 kbps», метка Lossless/Hi-Res — только когда так есть); у каждого трека — лицензия и ссылка на источник, на страницах релиза и исполнителя — полные строки атрибуции («Авторы и лицензии»). Внешние ссылки открываются в новой вкладке с `rel="noopener noreferrer"`.
- **Обложки** — генерируются из id (стабильный градиент и первая буква), помечены как декоративные (`aria-hidden`): в наборе нет обложек.
- **Кнопок «Играть» нет до I6** (BRIEF_v2 §12: никаких неактивных кнопок).
- Числа со склонением (`1 трек`, `3 трека`, `5 треков`) — `Intl.PluralRules` и ключи `count.*.{one,few,many,other}` в обоих языках.

## ADR-019 — Доставка аудио и движок плеера (итерация I6a)
**Статус:** Принято · 2026-11-05 · уточняет ADR-009 и ADR-010; Opus с откатом на AAC и полный движок — решения заказчика

**Доставка.**
- `GET /catalog/tracks/:id/stream` (после входа) отдаёт `TrackStream`: все рендиции трека (лучшая первой) с подписанными ссылками `/media/<token>` и громкость (EBU R128) для ReplayGain. Правило видимости — то же, что у каталога (ADR-018): непроигрываемый трек — 404.
- `GET /media/:token` отдаёт файл из S3 с поддержкой `Range` (206, 416), `Accept-Ranges`, `Cache-Control: private`. Заголовок `Authorization` не нужен: `<audio>` не умеет его отправлять, поэтому разрешение — сама ссылка. Токен — HMAC-SHA256 от {ключ объекта, размер, тип, срок}; ключ выводится из `AUTH_JWT_SECRET` через HKDF со своей меткой (отдельный секрет не нужен, ключи не совпадают). Срок — `MEDIA_URL_TTL_SEC`, по умолчанию 1 ч; ключ S3 клиенту не виден.
- Браузер ходит за файлами через тот же прокси `/api/*`, что и за API: один origin — Web Audio может обрабатывать звук (CORS не нужен). В production то же место займёт CDN с подписанными ссылками — интерфейс клиента не изменится.

**Выбор рендиции** (`@mp/player-core`, `chooseSource`): «авто» — лучшая lossy в порядке **Opus → AAC** (Opus там, где браузер его играет: `canPlayType`; иначе AAC — Safari/iOS); «экономия трафика» — самая лёгкая; «без потерь» — FLAC/Hi-Res, когда он есть. Выбор на клиенте: сервер не знает, что умеет браузер.

**ReplayGain:** усиление = ReplayGain 2.0 (−18 LUFS) + предусилитель (±6 дБ), но не больше, чем оставляет true peak ≤ −1 dBTP (запас на декодирование lossy). Режим «выкл.» — без усиления.

**`@mp/player-core`** (чистый TS, без DOM, тесты на всё): очередь (исходный порядок и порядок воспроизведения; shuffle Fisher–Yates с текущим треком первым и возвратом к исходному порядку; repeat off/all/one; «играть следующим», «в конец», удаление, перестановка; снимок для восстановления сессии), конечный автомат плеера, «назад» перезапускает трек после 3 с, пропуск непроигрываемых треков (не больше 5 подряд), однократное обновление истёкшей ссылки с той же позиции, ошибка сети — остановка с возможностью повторить. Платформу описывает интерфейс `AudioEngine`; **автоматический переход на следующий трек делает движок** — только так стык может быть точным до сэмпла.

**`@mp/audio-web`** (браузер и WebView2 в Windows):
- **Две «деки».** `BufferDeck` — файл целиком декодируется в `AudioBuffer` и запускается по часам `AudioContext`: стык без паузы (gapless) и crossfade точны до сэмпла. `ElementDeck` — потоковый `<audio>`: старт сразу, без загрузки всего файла. Первый трек после клика играет через `<audio>` (быстрый старт), следующий заранее скачивается и декодируется (за 45 с до конца текущего — чтобы держать в памяти не больше двух треков). Треки длиннее 15 минут не декодируются (час звука в памяти — около 1 ГБ) и играют потоком. Если браузер не смог декодировать файл, трек тоже играет потоком.
- **Честное ограничение:** стык «первый трек (поток) → второй» точен до ~10–50 мс, а не до сэмпла; все следующие стыки — точные.
- **Crossfade** — равномощная кривая (sin/cos) на усилениях дек, не больше половины любого из двух треков; внутри одного релиза по умолчанию gapless (концертные альбомы, классика, миксы). 0 с — gapless везде.
- **Эквалайзер** — 10 полос (31 Гц … 16 кГц, полка снизу и сверху, пики посередине, ±12 дБ), предусилитель снижает сигнал на величину наибольшего подъёма — эквалайзер не перегружает; пресеты. **Громкость** — квадратичная кривая; пауза, продолжение и перемотка — с плавным изменением громкости 30 мс (без щелчков); пауза останавливает `AudioContext` целиком.
- **Media Session** — название, исполнитель, альбом на экране блокировки и в системном оверлее, медиаклавиши, кнопки гарнитуры, перемотка из системы.

**Последствия.** Интерфейс плеера (нижняя панель, полноэкранный плеер, мини-плеер, горячие клавиши, сохранение сессии, кнопки «Играть») — I6b, по референсам 1 и 2 (`docs/references/`). Отчёты о прослушивании (`play_events`) — I7 вместе с историей. Нативный мобильный движок реализует тот же `AudioEngine` (Phase 3).

**Уточнение (2026-11-05) — интерфейс плеера (I6b).**
- **Один плеер на вкладку и пользователя** (`apps/web/lib/player-context.tsx`): `Player` + `WebAudioEngine` + резолвер ссылок каталога, Media Session, горячие клавиши. Создаётся на клиенте после входа и уничтожается при выходе — звук не переживает смену аккаунта.
- **Разблокировка звука:** браузеры разрешают звук только после действия пользователя, а трек стартует после сетевого запроса. Поэтому каждое нажатие «Играть» (кнопкой или клавишей) сначала синхронно создаёт и запускает `AudioContext` (`engine.unlock()`), а уже потом запрашивает ссылку.
- **Где плеер:** десктоп — панель внизу на всю ширину (реф. 1): трек со ссылками на релиз и исполнителя, перемешивание / назад / играть / вперёд / повтор, прогресс с перемоткой, честная метка формата («Opus 128 kbps»), очередь, громкость. Телефон — мини-плеер над нижней навигацией (реф. 2). Полноэкранный плеер (диалог, Escape, возврат фокуса): круглая обложка в кольце прогресса (реф. 2), ±10 с, громкость, вкладка «Очередь» (переход, удаление). Панель появляется, только когда что-то в очереди.
- **«Играть»:** номер трека в любом списке превращается в кнопку (текущий трек подсвечен, повторное нажатие — пауза); «Слушать» и «Вперемешку» у релиза, исполнителя и «Треков дня». Очередь — список, из которого начали (контекст).
- **Сессия** — снимок очереди и позиции в `localStorage` на аккаунт (каждые 5 с, при скрытии вкладки и закрытии), только нужные поля трека, не больше 500 треков; после перезагрузки плеер восстанавливается на паузе с той же позиции. Повреждённые данные игнорируются.
- **Настройки воспроизведения** (страница аккаунта, на устройстве): качество (лучшее / экономия / без потерь), выравнивание громкости, crossfade 0–12 с, «альбомы без переходов», эквалайзер на 10 полос с пресетами. Применяются сразу; новое качество — со следующего трека.
- **Горячие клавиши:** пробел / K — играть или пауза, ← → — 10 с, Shift + ← → — трек назад / вперёд, M — без звука. Не срабатывают в полях ввода, на ползунках и (пробел) на кнопках.
- Отчёты о прослушивании и синхронизация очереди между устройствами — I7.

## ADR-020 — Библиотека и синхронизация (итерация I7)
**Статус:** Принято · 2026-11-05 · уточняет ADR-011; объём I7, дубли и история — решения заказчика. Подробно — `docs/I7_PLAN.md`.

**Решение.**
- **Журнал изменений:** `users.change_seq` + `user_change_log`. Каждая мутация — одна транзакция: `change_seq + 1` (блокировка строки пользователя упорядочивает изменения) → данные → запись журнала → ключ идемпотентности; после коммита — `PUBLISH` в Redis. Мутации принимают `Idempotency-Key`; повтор возвращает сохранённый ответ. Журнал — 90 дней, отставший клиент получает `410` и перезагружает библиотеку целиком.
- **WebSocket только уведомляет** (`{ type: "changed", seq }`), данные — через `GET /sync/changes?since=`. Один путь данных с правами и валидацией; потеря WS ничего не ломает. `ws` (не socket.io) — проще для нативных клиентов. Подключение — по одноразовому билету на 30 с (`POST /sync/ws-ticket`), access-токен не попадает в URL.
- **Библиотека:** лайки треков, сохранённые альбомы, подписки на исполнителей (решение заказчика — в I7), плейлисты, история прослушиваний, настройки воспроизведения на сервере.
- **Плейлисты:** позиции — дробные строковые ключи (вставка и перестановка без перенумерации и без конфликтов между устройствами); удаление — tombstone. **Дубли разрешены с предупреждением** (решение заказчика): без `allowDuplicates` сервер отвечает `409 duplicate_tracks`.
- **Недоступный трек** (право истекло) остаётся в плейлисте и «Любимых» с меткой «Недоступно» и не играется.
- **История:** включена по умолчанию, «Очистить» и режим «Не записывать» (решение заказчика); при выключенном режиме сервер игнорирует отчёты. «Прослушивание» — от 30 с или половины трека.
- **Клиент:** новый пакет `@mp/sync` (чистый TS): outbox с идемпотентными мутациями, оптимистичное применение, повторы, откат при 4xx, курсор `seq`; хранилище — IndexedDB в вебе (SQLite на мобильных в Phase 3).

**Изменение плана.** Синхронизация очереди и позиции воспроизведения между устройствами (в ADR-019 отнесена к I7) переносится в Phase 3 вместе с Handoff: без второго типа клиента её не проверить по-настоящему, а критерию BRIEF_v2 §15.8 достаточно синхронизации библиотеки и настроек.

**Альтернативы.** Данные прямо в WS-сообщениях — два пути данных и сложнее догонять пропущенное. CRDT — избыточно для одного владельца плейлиста, вернуться в Phase 6 (совместные плейлисты). Целочисленные позиции — перестановка переписывает много строк и конфликтует при офлайне.

## ADR-022 — P0: безопасность публичного репозитория и медиассылок
**Статус:** Принято · 2026-11-05 · ТЗ v3 §3.1, §3.3, §XVI, PRIORITY 0; уточняет ADR-015 и ADR-019

**Решение.**
- **Утёкший пароль.** Пароль QA-аккаунта из публичного PROJECT_STATUS сменён через сброс пароля (старый → 401, ссылка сброса одноразовая). Учётные данные — только в локальном `qa-account.local` (в `.gitignore`). История Git не переписывается (решение заказчика): аккаунт есть только в локальной dev-БД, старый пароль не действует.
- **Заглушки из `.env.example` в production.** Раньше проверялся только `AUTH_JWT_SECRET`. Теперь при `NODE_ENV=production` API не стартует, если в `AUTH_JWT_SECRET`, `DATABASE_URL`, `REDIS_URL`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` или `SMTP_PASSWORD` осталась заглушка (`change_me`, `dev_only`, `mp_dev_`). Сообщение называет переменную, но не её значение.
- **CSRF.** Refresh-cookie и так `HttpOnly; SameSite=Strict; Path=/api/auth`. Дополнительно `POST /auth/refresh` и `/auth/logout` принимают cookie только из браузерного запроса веб-приложения: `Origin` должен быть одним из `WEB_APP_URL`/`CORS_ORIGINS`; без `Origin` — `Sec-Fetch-Site` должен быть `same-origin`/`none`. Иначе 403. Клиент без обоих заголовков — не браузер, подделать его запрос с cookie пользователя нельзя (нативные клиенты передают токен в теле). Остальные эндпоинты авторизуются только заголовком `Authorization`, его чужой сайт отправить не может. Отдельный CSRF-токен не нужен: этого достаточно (OWASP: Fetch Metadata + проверка Origin).
- **Медиассылки — аудит.**

| Что | Состояние |
|---|---|
| Срок | `MEDIA_URL_TTL_SEC` по умолчанию **600 с** (было 3600), допустимо 60–3600 |
| Обновление | плеер берёт новую ссылку за **2 мин** до истечения (было 1 мин) — предзагрузка и перемотка получают свежую; ошибка источника при игре → одно обновление и продолжение с той же позиции, после восстановления игры — снова доступно (long play) |
| Подпись | HMAC-SHA256 {ключ объекта, размер, тип, срок}, ключ из `AUTH_JWT_SECRET` через HKDF; подделка/истечение → 403 (тесты) |
| Range | 200 / 206 / 416, `Accept-Ranges` (тесты) |
| Передача третьим лицам | Ссылка — bearer-токен на 10 мин и один файл. Привязки к пользователю/IP нет (`<audio>` не отправляет заголовки, IP меняется у мобильных). Для коммерческого каталога — короткий срок + CDN с подписанными URL (P8) |
| Кэш | `Cache-Control: private, max-age=<остаток срока>`: браузер может держать файл, общие кэши — нет |
| Логи | Токен в пути (`/media/<token>`) теперь маскируется (`/media/:token`) в логе запросов, ответе rate limit и `instance` ошибок. Запрос шёл в логи с полным токеном — исправлено |
| Разделение источников | Ссылка подписывает конкретный объект; права источника проверяются при выдаче (`/stream`) — Rights Resolver (ТЗ v3 §3.2) в P1/P2 |

**Не входит (дальше по плану).** Rights Resolver с регионом пользователя, OAuth/OIDC, экспорт и удаление аккаунта — ADR-021, п. 3 и 10.

## ADR-023 — Rights Resolver: территории, статус лицензии, страна слушателя
**Статус:** Принято · 2026-11-05 · ТЗ v3 §3.2; способ определения страны — решение заказчика; уточняет ADR-018

**Решение.**
- **`apps/api/src/rights/rights-resolver.ts`** — одна чистая функция `resolveRights(rights, { mode, country, now })`: можно, если хотя бы одно право активно (`status = active`), разрешает режим (`stream` / `offline` / `preview`), действует сейчас (`valid_from` ≤ now < `valid_to`) и действует везде (`territories IS NULL`) или в стране слушателя. Иначе — отказ с причиной (`no_rights`, `inactive`, `mode_not_allowed`, `not_yet_valid`, `expired`, `territory`, `region_unknown`). **Fail closed:** нет прав или неизвестна страна для территориального права → нельзя.
- **SQL-двойник.** Видимость каталога (ADR-018) по-прежнему считается в PostgreSQL одним условием `CURRENT_STREAM_RIGHT`, теперь с тем же правилом. Страна передаётся транзакционной настройкой `mp.country` (`withCountry`), поэтому соединения пула её не наследуют. Отсутствие настройки (smoke-тест, CLI) = страна неизвестна.
- **Двойная проверка перед выдачей ссылок.** `GET /catalog/tracks/:id/stream` дополнительно прогоняет права трека через `resolveRights` и подписывает ссылки только при разрешении.
- **Страна слушателя** — только из заголовка CDN/прокси, имя задаётся `GEO_COUNTRY_HEADER` (например, `cf-ipcountry`). Значения `XX`, `T1`, `A1`, `EU` и т. п. и всё, что не две латинские буквы, — «неизвестно». Без настройки заголовок игнорируется: клиент не может сам выбрать страну и обойти ограничения (ТЗ v3 §3.2). Включать — только когда все запросы идут через этот прокси, который перезаписывает заголовок.
- **Статус лицензии** — новое поле `track_rights.status` (`active` / `suspended` / `revoked`, по умолчанию `active`), миграция генерируется `pnpm db:generate`.

**Альтернативы.** Своя база GeoIP (MaxMind) — регистрация, лицензия и обновления; не нужна, пока перед API стоит CDN. Страна из профиля пользователя — легко подменить. Территории как запрет (deny-list) — не нужно, пока все договоры описывают разрешённые страны.

**Не входит.** Требования конкретных поставщиков (подписка, лимит превью) — вместе с адаптерами поставщиков в P5. Офлайн-режим использует `mode: 'offline'` — в P4. Listen Together проверяет права каждого участника тем же резолвером — P7.
