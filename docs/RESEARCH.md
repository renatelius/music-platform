## 1. Анализ концепции

### Что реально делают лидеры и где у них слабые места

| Сервис | Сильная сторона | Слабое место, которое мы закрываем |
|---|---|---|
| Spotify | Персонализация (Discover Weekly, Daily Mix), Connect, Wrapped | Lossless появился поздно; рекомендации — «чёрный ящик»; локальные файлы — второй сорт |
| Apple Music | Lossless/Hi-Res, Spatial, премиальный UI | Закрытая экосистема, слабый Windows/Android-клиент, слабое открытие нового |
| YouTube Music | Огромный каталог версий, клипов, live, ремиксов | Хаос метаданных, смешение UGC и официального без явной маркировки |
| Яндекс Музыка | «Моя волна» — бесконечный адаптивный поток | Региональная ориентация |
| Deezer | Flow, тексты | Слабая дифференциация |
| Tidal | Качество и богатые метаданные (кредиты) | Слабые рекомендации, узкая аудитория |
| SoundCloud | Независимые артисты, загрузки | Качество звука, «грязный» каталог, слабый плеер |

**Вывод.** Ни один сервис не объединяет одновременно: (1) честное качество звука, (2) объяснимые рекомендации, (3) единую библиотеку «стриминг + независимые + своя коллекция», (4) равноценные клиенты на Windows/Android/iOS/Web. Это и есть наша ниша.

### Главные риски концепции (не скрываем)

1. **Лицензии — главный барьер, а не код.** Мейджор-каталог (Universal, Sony, Warner) требует договоров, авансов и минимальных гарантий. Без них «конкурировать со Spotify по каталогу» невозможно. Код мы строим так, чтобы каталог подключался без переписывания, но сами договоры — бизнес-задача.
2. **UGC и пиратство.** Загрузки исполнителей и пользователей — главный юридический риск. Нужны проверка прав, audio fingerprinting и процедура жалоб (notice-and-takedown) до публичного запуска загрузок.
3. **Четыре клиента одной командой.** Решается максимальным переиспользованием TS-кода (см. ARCHITECTURE §3).
4. **Аудиодвижок на 4 платформах.** Gapless/crossfade/ReplayGain ведут себя по-разному в браузере, WebView2, Android и iOS — отдельная инженерная задача (см. ADR-010).

## 2. Три варианта позиционирования

### A. «Audiophile Hub» — платформа честного звука
Лучшее качество, прозрачные форматы (видно реальный кодек/битрейт/источник), кредиты и метаданные уровня Tidal, bit-perfect на Windows.
- ➕ Чёткая аудитория, высокая готовность платить.
- ➖ Узкий рынок; без мейджор-каталога не работает.

### B. «Universal Library» — одна библиотека для всей музыки человека
Стриминг, независимые артисты, своя коллекция и локальные файлы — в одной библиотеке, на всех устройствах, с честной маркировкой источника. Рекомендации работают по всей библиотеке.
- ➕ Ценность есть **даже без мейджор-каталога**: своя коллекция + независимые артисты + CC-музыка. Реалистичный старт.
- ➖ Сложнее объяснить в одной фразе; облачное хранение личных файлов стоит денег.

### C. «Discovery First» — платформа открытия музыки
AI DJ на естественном языке, объяснимые рекомендации, Hidden Gems, Global Radar, сильная витрина независимых артистов.
- ➕ Яркая дифференциация, вирусный потенциал (Music DNA, Timeline).
- ➖ Качество рекомендаций зависит от объёма данных — на старте их мало (проблема холодного старта).

### Рекомендация CPO
**B как фундамент + C как витрина + A как премиум-опция.** Это совпадает с принятым гибридным каталогом (ADR-002): продукт полезен с первого дня (своя музыка + независимые), а открытие нового и качество звука становятся причинами платить.

Слоган-черновик: *«Вся твоя музыка. Любой источник. Любое устройство. Честный звук.»*

## 3. Конкурентные преимущества

1. **Единая библиотека** — стриминг + независимые + личная коллекция + локальные файлы, с явной маркировкой источника и прав.
2. **Честный звук** — в плеере всегда виден реальный формат цепочки: источник → кодек → битрейт/частота → устройство. Никаких «Lossless» на сжатых файлах.
3. **Объяснимые рекомендации** — у каждой рекомендации есть «почему» («похоже на X, который вы переслушали 12 раз», «новый релиз артиста, которого вы слушаете по вечерам»).
4. **Равноценные клиенты** — Windows-приложение не хуже мобильного; Handoff между устройствами за 1 клик.
5. **Справедливость для артистов** — прозрачная статистика и понятная модель выплат в Artist Studio.
6. **Работа на плохом интернете** — адаптивный выбор качества, предзагрузка следующего трека, офлайн-очередь действий.

### Дополнительные идеи, которые реально выделяют продукт
- **Listening Handoff** — «продолжить на телефоне» с точной позицией и очередью.
- **Source Transparency Badge** — значок источника и лицензии у каждого трека.
- **Taste Control** — пользователь сам правит свой вкусовой профиль («меньше рэпа по утрам»), а не только кнопкой «не нравится».
- **Credits Graph** — граф продюсеров, сессионных музыкантов, авторов; переход «всё, где играл этот барабанщик».
- **Fair Pay View** — сколько из подписки пользователя ушло его артистам (user-centric модель выплат как опция).
- **Local-first режим** — Windows-клиент как полноценный плеер локальной FLAC-коллекции, даже без подписки.

## 4. Карта экранов

```
Онбординг ─ регистрация/вход ─ выбор языка ─ выбор вкусов (холодный старт)
│
├── Главная (персональная лента: продолжить, миксы, новинки, Hidden Gems)
├── Поиск ── результаты (треки/альбомы/артисты/плейлисты/тексты) ── фильтры (жанр, год, язык, настроение)
│            └── AI DJ (запрос на естественном языке)          [Phase 5]
├── Библиотека ── Любимые ── Плейлисты ── Альбомы ── Артисты ── Моя коллекция ── Скачанное ── История
├── Альбом ── трек-лист, кредиты, формат/качество, источник и лицензия
├── Исполнитель ── популярное, дискография (альбомы/синглы/EP/live), похожие
├── Плейлист ── редактирование, совместный доступ                [совместный — Phase 6]
├── Плеер: мини-плеер (всегда) ── полноэкранный ── очередь ── текст ── устройства (Handoff) ── эквалайзер
├── Статистика / Music DNA / Timeline                            [Phase 5]
├── Профиль ── публичный профиль, приватность                    [социальное — Phase 6]
├── Настройки ── качество, язык, тема, устройства, приватность, аккаунт, экспорт данных
├── Подписка ── тарифы, оплата, семья/студент                    [Phase 6]
│
├── Artist Studio (отдельное приложение)                         [Phase 4]
│   └── профиль артиста ── релизы ── загрузка ── права ── статистика ── выплаты
└── Admin Studio (отдельное приложение)                          [Phase 4+]
    └── пользователи ── каталог ── модерация ── жалобы ── рекомендации ── здоровье системы
```

### Ключевые пользовательские сценарии (MVP)
1. **Первый вход:** регистрация → выбор языка/темы → главная с каталогом → первый трек < 60 с от открытия.
2. **Поиск и прослушивание:** ввод запроса → мгновенные подсказки → альбом → воспроизведение → следующий трек без паузы (gapless).
3. **Сохранение:** ♥ трека → он сразу появляется в «Любимых» на другом открытом устройстве.
4. **Плейлист:** создать → добавить из поиска/альбома → переупорядочить → воспроизвести.
5. **Handoff** (Phase 3): слушаю на Windows → открываю телефон → «Продолжить здесь» с той же позиции.

## 5. Легальные источники музыки

| Источник | Что даёт | Условия | Когда |
|---|---|---|---|
| **Free Music Archive (FMA) датасет** | ~106 тыс. треков под Creative Commons, 161 жанр ([HF dataset](https://huggingface.co/datasets/benjamin-paine/free-music-archive-full)) | Лицензия **у каждого трека своя**. Берём только CC0 / CC BY / CC BY-SA; NC и ND исключаем из коммерческой витрины. Обязательна атрибуция | **MVP — тестовый каталог** |
| **Jamendo API** | ~500 тыс. CC-треков, поиск, радио, OAuth2 ([docs](https://developer.jamendo.com/v3.0/docs)) | Бесплатно **только для некоммерческого** использования, для коммерции — договор ([условия](https://help-licensing.jamendo.com/hc/en-us/articles/20699346005661-Jamendo-API)) | Dev/прототип; коммерция — по договору |
| **MusicBrainz** | Открытая база метаданных (артисты, релизы, кредиты, ID) | Ядро данных — CC0; лимиты на API, для объёма — свой зеркальный дамп | Phase 2–4 (обогащение метаданных) |
| **Cover Art Archive** | Обложки по MusicBrainz ID | Права на обложки у правообладателей — использовать только для привязанных релизов | Phase 4 |
| **Тексты песен** | Синхронизированные тексты | Тексты — объект авторского права (издатели). Для коммерции нужен лицензированный провайдер (LyricFind / Musixmatch — проверить условия). Открытые базы (например LRCLIB) — только после юридической проверки | Phase 4–5 |
| **Независимые артисты** | Собственные загрузки | Договор-оферта с артистом + подтверждение прав + fingerprinting | Phase 4 |
| **Лицензированные каталоги** | Мейджоры и инди-лейблы | Прямые договоры или через дистрибьюторов; поставка метаданных и аудио по стандарту **DDEX ERN**; отдельно — авторские права (издатели/общества) | После юрлица и финансирования |
| **Личная коллекция** | Файлы пользователя | Только для самого пользователя, без публичной раздачи | Phase 4 |

**Важно:** Spotify/Apple Music/YouTube Music API **не дают права** транслировать их аудио в нашем приложении. Их можно использовать только для **импорта списков плейлистов** (названия треков → сопоставление с нашим каталогом) по их правилам для разработчиков.

| CDN | Cloudflare / CloudFront / Bunny | Phase 6 | Аккаунт |

| Подпись Windows-приложения | Сертификат подписи кода (или Microsoft Store) | Phase 7 | Сертификат |
| Платежи | Stripe / Paddle (веб); App Store / Google Play Billing (в приложениях) | Phase 6 | Юрлицо; выбор провайдера зависит от страны регистрации |

| Метрики/логи | Prometheus + Grafana + Loki (self-hosted) | Phase 5–6 | — |

| Embeddings / LLM для AI DJ | Свой ML-сервис (Python) + опционально внешний LLM | Phase 5 | Ключ провайдера LLM (по выбору) |

Для каждой ещё не подключённой интеграции в приложении будет **честный статус** («не подключено — нужен ключ X»), а не фальшивая работа (BRIEF_v2 §12).
